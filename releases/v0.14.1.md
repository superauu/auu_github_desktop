# AuuGit v0.14.1 · 仓库快照架构专项

本版落地 repo_snapshot 架构专项：把仓库数据面的轮询与刷新从「多条独立 IPC + 多个 git 进程」合并为「一次聚合快照」，并给全局并发闸加上传输类优先级。功能行为零变化，进程数与 IPC 往返显著下降。

## 仓库聚合快照（一次 IPC 拿全数据面）

- 新增 Rust 聚合命令 `git_repository_snapshot`：一次 IPC 内并行跑一组**固定只读形态**命令（status / for-each-ref / worktree list / remote -v / stash list / log / 操作态探测 / 协作偏好），全部经策略层逐条校验；dev 桥 `/api/git-snapshot` 提供同构端点（web 预览全链路一致）。
- **安静轮询 tick**（外部变更检测）：5 次 IPC → **1 次**；**全量刷新**（打开仓库/refs 变化后的 refreshAll）：8+ 次 IPC → **1 次**。git 进程数同步下降：refs 指纹 + 分支 + 标签三条命令并入一条 for-each-ref，协作偏好两条 `config --get` 并成一条 `-z --get-regexp`，`remote -v` 不再在同一刷新里跑两遍，`openRepository` 的重复仓库校验与重复解析一并免除。
- 返回原始 stdout，解析复用既有解析器（零重复实现）；空仓库的 log 与无匹配配置的 `config --get-regexp`（退出码 1）按预期容错，与旧路径行为一致。

## 并发闸传输类优先

- 全局并发闸（8 槽）由先到先得改为**两档优先级**：push / fetch / pull / clone / ls-remote / lfs push·pull 归传输类（剥掉 `-c` 全局前缀后按子命令判定——应用所有调用都带该前缀），传输类等待时背景类（状态轮询 / 快照 / 读写）不再进入空槽。
- 消除的饿死方向：状态类碎片调用洪泛时，用户显式的传输动作此前可能无限期排队。

## 跳过的项（决策记录）

- 传输授权解析缓存：评估后**不做**——remote set-url 后的 TTL 窗口内会用旧 URL 放行越界 file 目标（安全边界弱化），而收益仅为每次传输约百毫秒级的前置解析。

## 测试

- node 全量 **737**、Rust 测试 **80** + clippy `-D warnings`、e2e integrations **3** 全绿；新增真仓库测试锁定快照与独立数据面的输出等价（指纹逐字节同构、分支归属/isCurrent 标注、tag 双形态、stash、空仓库容错）与并发闸优先级语义（分类剥前缀 + 有传输等待者时背景类不插队）。

---

Version 0.14.1 lands the repo_snapshot architecture project: a single aggregated snapshot IPC (new `git_repository_snapshot` command plus a matching dev-bridge endpoint) replaces the 5 separate IPC round-trips of a quiet polling tick and the 8+ of a full refresh, with a combined for-each-ref serving fingerprint/branches/tags and a merged config regexp serving the collaboration preference — raw stdout returns to the existing parsers, so behavior is unchanged while process counts drop. The global concurrency gate (8 slots) gains transport-priority admission: push/fetch/pull/clone/ls-remote/lfs push·pull (classified after stripping the `-c` global prefix) pre-empt background waiters, eliminating the starvation direction where status-class floods delayed explicit transports. Transport authorization caching was evaluated and intentionally skipped: a stale-URL TTL window could authorize out-of-bounds file targets after `remote set-url`, and the win is only ~100 ms per transport. Test base: 737 node, 80 Rust, clippy clean, 3 e2e integration specs.
