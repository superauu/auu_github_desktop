# 代码审核使用指南

> 💡 单文件 HTML 版:[review-guide.html](review-guide.html)——双击即可离线查看。

代码审核集中在「工作区变更」中完成，再按需要暂存或提交。已提交内容可在「提交历史」中查看单次差异。

## 提交前：在工作区审核

1. 在「工作区变更」选择文件，在差异中逐块通过，或点击「通过此文件」。
   左侧文件列表会显示「已审核」「待审核」、部分代码块的审核进度或未解决意见数，顶部汇总已审和待审数量。同一文件的暂存与未暂存内容分别显示状态；内容刷新后会重新核对审核标记。
   连续审核时可用「通过并继续」通过当前文件并打开下一个待审核版本，也可用「下一个待审核」跳过当前文件。已审核项和冲突文件会跳过，暂存与未暂存版本分别导航。窄列表中状态显示为图标，悬停可查看完整说明。
   审核进度旁的「全部审核通过」可批量通过当前工作区各文件版本；待解决意见、冲突或读取失败的文件会跳过并提示。该操作只记录审核状态，后续代码改动仍需重新审核。
   可按文件名、路径（含重命名前路径）搜索，并筛选待审核、有待解决意见、已审核文件。筛选后「通过筛选结果」及暂存、取消暂存只处理显示的文件版本，「下一个待审核」也在筛选结果中导航。
   批量审核显示读取进度，可以取消；取消后本批次不会新增通过记录。读取失败后可只重试失败文件。
2. 用代码块的评论按钮或「审核意见」记录问题，修复后标记为已解决，再通过审核。
   如需交给 AI 修改，点击差异工具栏的「AI 修复报告」：报告汇总当前仓库、当前分支所有文件的意见和记录时的原始代码片段，支持预览、复制，以及选择包含已解决意见。代码变化后先核对上下文；未保存原始片段的旧意见会明确提示。
   报告默认只包含当前工作区变更文件的待解决意见；已提交或不在当前变更中的文件意见默认收起，可勾选「包含历史文件意见」查看。点击「管理意见」可查看本仓库、本分支全部意见，直接标记已解决或删除，删除支持撤销；工作区干净时也可管理旧意见。
   意见输入支持 Ctrl/⌘+Enter 保存；关闭意见面板或切换文件不会丢失当前会话的草稿，草稿按文件、差异版本与代码块分别保留，关闭应用后清除。删除意见后可在提示中「撤销」。若本地存储失败，审核面板会提示记录仅保留在内存中，请在关闭应用前「重试保存」。
   在意见卡片中可「编辑意见」或「定位代码」。定位会选择对应的暂存或未暂存版本并滚动、高亮原代码块；原块已变化时只打开当前文件并提示核对。编辑保留原始代码上下文，检测到并发修改时保留草稿并提示，不覆盖新内容。
3. 按需要暂存文件或代码块。相同内容暂存后保留审核状态，后续修改需要重新审核；审核标记和暂存状态分别记录。
4. 提交时只检查本次包含的内容。未审核内容和未解决意见默认会提醒，可选择「返回审核」或「继续提交」，不会强制要求审核通过。
5. 可在「设置 → Git → 提交前提醒未审核内容」随时开关提醒，也可在弹窗中勾选「不再提醒」。关闭提醒后仍可手动审核。

进行中的审核状态和意见临时保存在本机，重开应用可继续。文件提交或撤销修改、不再属于工作区变更后，只有通过标记或全部意见已解决的记录会自动清理；未解决意见继续保留，可在「管理意见」中处理。同一文件仍有未提交修改时保留记录，其他仓库或分支的记录不受影响。不提供审核数据备份；这些记录不写入代码，也不会推送到远端。

## 查看已提交的改动

进入「提交历史」，选择提交和文件即可查看差异。提交图、搜索、追溯和整理提交继续可用。
